# Development Log

## 2026-10-31 — M0 → M5
- Workspace audit: the repo contained only `SourceFiles/` (Synty source sprites + Oxanium font). The `.unitypackage` was absent.
  `ASSET_INVENTORY.md` was generated by script (2,131 files, dimensions/modes).
- Engine: evaluated UE5 / Godot 4 / Unity / custom. Unity download hosts are blocked (403) and need a licence; UE5 needs a source
  build for servers. Godot 4.3 downloaded and verified with export templates → selected (`ENGINE_EVALUATION.md`).
  The user confirmed Godot over an unverifiable Unity project.
- Built: autoloads (Log, GameData, Settings, Net, Session), data JSON, player motor/health/inventory, prediction controller,
  first-person rig, third-person soldier model, enemy AI, mission director, equipment, industrial map, FX, procedural audio,
  UI kit + all screens, headless test bot, build + test scripts.
- Bugs found by tests and fixed:
  - GDScript type-inference errors and a `request_ready` override clash.
  - Discrete actions (crouch/reload/switch) are event-driven → the test bot now injects `InputEventAction`s.
  - **Server extrapolated inputs when the queue was empty** → prediction drift and 30% faster movement after reconciliation.
    The server now simulates each client input frame exactly once (drift 0.000 m, speed 3.38/3.40 m/s).
  - The server kept streaming snapshots after results, so clients that had already freed the World logged "node not found" → replication stops at mission end.
  - Auth secrets were keyed by address:port, so returning players were rejected on another port → keyed by a persistent server realm id.
  - Map randomness differed between client and server → fixed RNG seed for identical collision.
- Verification: 45/45 co-op checks (source + exported Linux build), 30/30 in rendered 2-player session, persistence across runs.

## 2026-10-31: Download website
- Added `server/WebPortal.gd`: the dedicated server now hosts a download page (`--http-port`, default 8080) that serves the
  Windows client zip from `<server dir>/downloads/`. `tools/build.sh` now produces `dist/OperationBlackout-Windows.zip` and
  `dist/OperationBlackout-Server-Linux.zip` (the server bundle includes the client zip in `downloads/`).
- Verified with the exported server: page, status JSON, full download with matching checksum, 404/405 handling; co-op regression 45/45.

## 2026-10-31: ARM64 dedicated server
- Added the "Linux Dedicated Server ARM64" export preset and `dist/OperationBlackout-Server-Linux-ARM64.zip` (for Ampere hosts).
  `run_server.sh` now restores the exec bit and cd's to its own folder (panel uploads often drop permissions).
- Verified under qemu-aarch64: the server boots, the website serves the client, and the 4-bot mission completes (44/45; walk speed
  slowed by emulation). `run_coop_test.sh` accepts `BOT_ARGS` and `SERVER_BOOT`.

## 2026-10-31: Multi-room dedicated server
- One server now hosts many rooms (squads of up to 4) instead of one 4-player squad: `server/Room.gd`, room-aware `Session`,
  per-room isolated World (SubViewport + own World3D). Room browser with CS:GO-style filters, create/join with optional password;
  server browser with Favorites/History and live status and ping. Website lists rooms. Protocol bumped to `blackout-0.2`.
- Fixed a client crash: after mission end the HUD kept reading the freed world's camera. The UI is now disabled before the world is freed.
- Test: 6 clients / 3 rooms / 2 concurrent missions → 93/93 on the exported build. ARM64 build boots under emulation and serves status.

## 2026-10-31: Visual overhaul (supplied Synty assets + procedural 3D)
- Re-audited `SourceFiles/` and checked `master` for new uploads: the pack is 2D only (HUD sprites, textured frames, icon sets,
  prop/weapon renders, badges, FX, cursors, input prompts, sample screenshots and portraits, and a font). It has no 3D models,
  textures or audio.
- UI: new theme built from MilitaryCombat textured boxes and bars. Additions: sample-screenshot backdrops, operator portraits in metal
  frames, rank badges, colour weapon renders, item renders in hex sockets, DMR scope overlay, deployment loading screen with the
  Synty spinner, and the Synty cursor.
- World: rebuilt OP-01 with chamfered low-poly architecture (corrugated warehouse with plinth, columns, trusses and skylights;
  brick maintenance block; perimeter with pillars and razor wire), detailed props (containers, trucks, forklift, racks, pallets,
  barrels, sandbags, guard tower, tanks, generator, fences, lamps), procedural PBR materials, decals, signage, Dominion banners,
  warm haze lighting, SSAO/SSIL, volumetric fog and dust. Colliders are unchanged, so gameplay and AI navigation are identical.
- Characters: Task Force operators (arid camo, plate carriers, helmets with goggles or NVG, class patches) and Dominion rifleman, heavy,
  spotter and officer variants, each holding real weapon models.
- Weapons: 5 detailed models whose silhouettes follow the supplied side renders. They have open-window optics for ADS, gloved hands and
  a muzzle flash from the supplied glow sprite.
- Dedicated server: `Geo.visuals = false`, so it builds no meshes, materials or textures, and the server export excludes `assets/*`
  (pck 371 KB). Fixed a first-use texture-generation stall by pre-generating materials at load (120 ms).
- Verification: 93/93 multiplayer checks (exported build), rendered Forward+ screenshots, Windows and Linux (x86_64/ARM64) exports.
